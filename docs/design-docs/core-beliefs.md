# Core Beliefs

에이전트 우선(agent-first)으로 이 레포를 운영하기 위한 원칙.

## 1. 레포가 기록 시스템이다

Slack, 노션, 머릿속 지식은 에이전트에게 존재하지 않는다. 결정·스펙·계획은 `docs/`에 남긴다.

## 2. 지도를 주고, 백과사전은 주지 않는다

`CLAUDE.md`는 목차다. 200줄을 넘기지 않는다. 상세는 `docs/`와 Skills로 점진적으로 공개한다.

## 3. 불변식은 강제, 구현은 자유

경계(레이어, 데이터 파싱, 비밀값, 네이티브 폴더)는 hook·스크립트로 기계적으로 막는다.
경계 안에서의 구현 방식은 에이전트에게 맡긴다. 사람 취향의 문체 차이는 결함이 아니다.

## 4. 막힘은 하네스 결함의 신호

에이전트가 실패하면 "더 노력"하지 않는다. 빠진 도구·문서·가드레일을 찾아 레포에 추가한다.

## 5. 규칙은 승격된다

리뷰 코멘트 → 문서 → 린트/스크립트. 반복되는 지적은 코드로 승격한다.
스크립트 에러 메시지에는 **고치는 방법**을 적는다 (에이전트 컨텍스트에 주입되므로).

## 6. 지루한 기술을 선호

에이전트가 모델링하기 쉬운 안정적인 API를 고른다. 불투명한 라이브러리보다 작은 자체 구현이 나을 때도 있다.
새 의존성 추가 시 `docs/design-docs/`에 이유를 남긴다.

## 7. 기술 부채는 매일 조금씩 갚는다

`/cleanup`으로 드리프트를 작게, 자주 정리한다. 몰아서 갚지 않는다.
